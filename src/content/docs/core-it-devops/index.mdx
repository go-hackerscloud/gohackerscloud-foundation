# Core IT & DevOps — Learn how real systems work

**Seven foundation modules · Beginner to early intermediate · Free conceptual study and self-directed practice**

Most IT professionals are asked to solve problems that cross more than one technology. A website is not “a networking problem” or “a Linux problem”: its behavior depends on compute resources, operating systems, DNS, applications, identity, network paths and the change process. This pathway connects those pieces in the order you will need them at work.

You do **not** need an expensive laptop or a GoHackersCloud subscription to complete the free lessons and worksheets. Use the read-only commands only on systems you own or may administer. Later, if you want supported hosted practical exercises, the separate [GHC Labs overview](/ghc-labs/) shows how Academy tracks and subscriptions work.

## What you can build by the end

A short **“investigate a slow and unreachable application”** portfolio case. It will contain a system diagram, a network troubleshooting decision tree, Linux and Windows read-only checks, a Python log summarizer, and Git history showing how your investigation notes evolved.

This is a synthetic learning exercise, not proof of professional production experience.

## Architecture: how the modules connect

```text
                    User / browser
                          |
                   DNS + TCP + TLS
                          |
                    Web application
                   /       |        \
           Linux server  Windows   Managed service
                 |          |           |
                 +---- Logs and metrics +
                          |
                Python analysis script
                          |
              Git + reviewed DevOps change
                          |
                Evidence and retesting
```

Ask yourself: if the browser fails to load the application, how do you know whether the fault is DNS, TCP connectivity, a missing TLS certificate, a stopped process, disk pressure or an application error? The modules progressively answer those questions.

## Example professional investigation

A hypothetical retailer reports that the customer portal is sometimes slow, and users in one office cannot reach it. The junior engineer has no permission to change production settings.

1. **Clarify:** which users, what time, what symptoms, and what changed?
2. **Separate layers:** DNS answer, network path, TCP reachability, TLS, HTTP response, application dependencies.
3. **Observe safely:** read-only OS and network commands; avoid blindly restarting services.
4. **Document:** capture timestamps, commands, sanitized outputs, likely causes and unanswered questions.
5. **Escalate:** communicate evidence and a reversible next test to an authorized owner.
6. **Track changes:** use Git to preserve how the diagnosis evolved.

The professional skill is not “running every command”; it is selecting the next test that distinguishes two possible causes.

## A practical weekly routine

| Session | Time | Goal |
|---|---:|---|
| Read concepts | 20–30 minutes | Learn definitions and architecture |
| Try a safe example | 20–30 minutes | Inspect a real result |
| Write evidence | 10–15 minutes | Record what happened and why |
| Explain aloud | 10 minutes | Answer a scenario question without looking |
| Review | 10 minutes | Correct a misconception and plan what is next |

The suggested time is flexible. More complex modules may take several weeks. No paid access, certification or job outcome is guaranteed.

## Progress checks

- [ ] I can draw the flow from browser to server and name the network dependencies.
- [ ] I can explain CPU, memory, storage and why each affects performance.
- [ ] I can use basic Linux and Windows commands without modifying system state.
- [ ] I can read and create a basic Python script that processes synthetic data.
- [ ] I can explain what Git records and why review is important.
- [ ] I can describe an incident using facts, assumptions and next tests.
